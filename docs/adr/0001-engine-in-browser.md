# ADR 0001. Движок симуляции живёт в браузере

Дата: 2026-10-02 · Статус: принято

## Контекст

Бэкенд на .NET 10 появляется уже в MVP. Возник вопрос, где считать симуляцию: в браузере на TypeScript, на сервере на C# или в браузере через C# в WebAssembly.

## Решение

Движок — пакет `web/packages/engine` на чистом TypeScript, запускается в Web Worker. Сервер схемы не считает.

## Почему

- Пересчёт идёт на каждое движение ползунка. Сеть на каждый тик сделала бы доску вязкой.
- Приложение работает офлайн и без сервера: автосохранение, файл, ссылка в URL.
- C# в WASM добавляет второй рантайм и несколько мегабайт загрузки ради одной функции.
- Один движок вместо двух: нет расхождений между клиентом и сервером.

## Последствия

- Пакет не зависит от Angular и DOM, поэтому его можно запускать в Node для CLI и CI (этап 3).
- Если серверу когда-нибудь понадобится считать (например, превью для соцсетей), он запустит тот же пакет в Node, а не будет переписывать формулы.
